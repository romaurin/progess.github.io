# Progress — электронный журнал

## Запуск
Нужен Node.js 16 или новее. Внешние пакеты не нужны.

    node server.js

Откройте http://localhost:3000

## Первый вход
Роль выбирать не нужно: система определяет её по логину.
- Администратор: логин `admin`, пароль `admin12345`
- Директор: логин `director`, пароль `director123`
- Преподаватель: логин `teacher`, пароль `teacher123`
- Студент: логин `roma`, пароль `roma12345`

Пароли при первом запуске можно задать так:

    ADMIN_PASSWORD=... DIRECTOR_PASSWORD=... TEACHER_PASSWORD=... node server.js

В уже существующую базу администратор и директор добавляются автоматически при запуске. После первого входа смените пароли в разделе «Мой профиль».

Демо-пароли действуют, только пока не создан файл `data/db.json`.
Удалите папку `data`, чтобы сбросить базу к начальному состоянию.

## Вход через Google
- В Google Cloud Console создайте OAuth Client ID типа «Web application».
- В Authorized redirect URIs добавьте адрес callback, например `https://ваш-домен/auth/google/callback`. Для локальной проверки: `http://localhost:3000/auth/google/callback`.
- Задайте серверные переменные `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` и `GOOGLE_REDIRECT_URI`; включите HTTPS на рабочем хостинге. Не публикуйте Client Secret.
- Администратор должен предварительно привязать подтверждённый Google email к существующему аккаунту в разделе «Аккаунты». Новые аккаунты автоматически не создаются, роли Google-входом не назначаются.
- В OAuth consent screen добавьте нужных пользователей в тестовые аккаунты, пока приложение Google не опубликовано.

## Как это устроено
- Данные лежат на сервере в `data/db.json`. Пароли хранятся в виде хэша scrypt с солью (для проверки входа) и дополнительно в зашифрованном виде AES-256-GCM (чтобы куратор мог показать пароль студенту). Ключ лежит в `data/secret.key` или в переменной `SECRET_KEY`. Не публикуйте папку `data`.
- Вход через cookie-сессию (HttpOnly, живёт 8 часов). Сессии хранятся в памяти: после перезапуска сервера нужно войти снова.
- Студент видит только свои оценки и работы. Добавлять студентов и выставлять оценки может только преподаватель.
- Для публикации в интернете поставьте сервер за HTTPS (nginx, Caddy и т. п.).
- Файлы, которые студенты загружают в «Задания», лежат в `data/files/` (до 25 МБ). Преподаватель и сам студент могут их скачать, другие студенты нет.
- Сессии сохраняются в `data/sessions.json`, поэтому после перезапуска сервера входить заново не нужно.
- Если `data/db.json` окажется повреждённым, сервер сохранит копию рядом (`db.json.broken-…`), а не сотрёт данные молча.

## Кабинеты
- **Администратор**: «Состояние сайта» (проверки базы, диска, файлов, паролей по умолчанию, ошибок), «Аккаунты» (создание, сброс пароля, удаление любых пользователей), «Журнал событий» (входы, неудачные попытки, изменения, ошибки), свой профиль.
- **Директор**: добавление и удаление преподавателей, редактирование расписания (его видят все), объявления, студенты и оценки, свой профиль.
- Администратор, директор и преподаватель меняют свои ФИО, логин и пароль в «Мой профиль» (нужен текущий пароль).
- Расписание и объявления хранятся в `data/db.json`, журнал событий в `data/events.log`.

## Группы и расписание
- У каждой группы своё отдельное расписание. Директор открывает «Расписание», выбирает группу и редактирует только её таблицу.
- Студент автоматически видит расписание своей группы.
- При создании преподавателя можно выбрать одну или несколько групп, которые он ведёт. Эти группы отображаются в списке преподавателей и в профиле преподавателя.
- Преподаватель в разделе «Расписание» видит только закреплённые за ним группы и может переключаться между ними.
- При создании студента можно сразу назначить группу.
- В CSV для студентов можно указывать колонку «Группа». Для расписания первая колонка — «Группа», далее «Время; ПН; ВТ; СР; ЧТ; ПТ».
